# ARRS — платформа для АРГ (терминал + бэкенд + админка)

Полноценный full-stack проект:

- **Публичный сайт** — тот самый терминал (glitch-логотип, "плывущая" картинка, живой boot-лог, реальный `login:` / `password:`, ASCII-пасхалки со смехом) — но теперь **все данные тянутся с сервера**, а не зашиты в HTML.
- **Бэкенд** (Node.js + Express) — хранит профили, команды, цепочки, страницы и пасхалки в `data/db.json`. Пароли профилей хранятся как bcrypt-хеши, никогда не в открытом виде.
- **Админ-панель** (`/admin`) — защищённый редактор: добавляй/редактируй профили (со своим логином/паролем на каждый), кастомные команды терминала, цепочки-загадки, отдельные страницы и пасхалки — без единой строчки кода.
- **Логин и пароль от самой админки знаешь только ты** — они задаются переменными окружения `ADMIN_USERNAME` / `ADMIN_PASSWORD` прямо на сервере и **никогда не попадают ни в базу, ни во фронтенд, ни в git**.

---

## 1. Быстрый запуск локально

Нужен установленный Node.js (18+).

```bash
npm install
cp .env.example .env
```

Открой `.env` и впиши:
- `ADMIN_USERNAME` / `ADMIN_PASSWORD` — свои логин и пароль от админки (только ты их знаешь)
- `JWT_SECRET` — случайная длинная строка. Сгенерировать:
  ```bash
  node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
  ```

Запуск:
```bash
npm start
```

- Сайт: **http://localhost:3000**
- Админка: **http://localhost:3000/admin**

В комплекте уже лежит demo-профиль (логин `cooper` / пароль `pussycat`) — чтобы сразу увидеть, как всё работает. Отредактируй или удали его из админки, когда сделаешь свой.

## 2. Как устроена админка

Пять разделов, все редактируются как таблица + форма:

### Профили
Каждый профиль — это отдельное досье со своим **логином и паролем для входа на сайте** (это не пароль от админки — это то, что вводят игроки в терминале). Поля:
- Имя, позывной, штамп сверху
- Портрет — вставь прямую ссылку на картинку, или `data:image/jpeg;base64,...` если хочешь зашить файл прямо в базу
- Ссылка на аудиотрек (необязательно)
- **Мета-поля** и **статистика** — построчно в формате `label:value`
- **Разделы биографии** — можно с `<b>HTML</b>` внутри:
  ```
  ### Заголовок раздела
  Текст раздела, можно с <b>жирным</b>.
  ===
  ### Следующий раздел
  Ещё текст.
  ```
- **Теги** — через запятую
- **Прогресс-бары** — построчно `label:value:pct` (pct — число 0–100)

### Команды
Любое слово, которое игрок вводит в терминале (кроме встроенных `help`/`login`/`whoami`/`status`/`clear`), можно перехватить кастомным ответом. Привязывается либо к конкретному профилю, либо работает глобально (доступна ещё до входа).

### Цепочки
Набор кодов-загадок. Формат построчно:
```
код::сообщение при разгадке::slug открываемой страницы (необязательно)
10-4-KORD::Сигнал расшифрован. Координаты приняты.::coordinates
```
Игрок вводит код в терминал — если совпадает, видит сообщение и (если указан slug) ссылку на открывшуюся страницу `/page/slug`.

### Страницы
Отдельные HTML-страницы по адресу `/page/slug` — для лендингов-загадок, наград за прохождение цепочки и т.п.

### Пасхалки
Настраиваемые ASCII-анимации с "пиксельным" смехом (или коротким сигналом, или без звука). Два сценария:
- **Триггер `__wrong_login__`** — специальный зарезервированный триггер: срабатывает при неверном логине/пароле в терминале (по умолчанию там уже сидит смеющийся скелетик — можешь заменить своим ASCII-артом).
- **Любое другое слово-триггер** — секретная команда: если игрок введёт её в терминале, выскочит твоя пасхалка.

ASCII-кадры для анимации — просто нарисуй текстом; если хочешь анимацию из нескольких кадров, раздели их строкой `---FRAME---`.

### Настройки сайта
Название, подзаголовок и тег узла на главном экране терминала.

## 3. Модель безопасности (коротко)

- Пароль админки существует **только** в переменной окружения на сервере и в оперативной памяти процесса (хешируется при старте). Он не пишется ни в `data/db.json`, ни в куки, ни во фронтенд.
- Сессия админки — HttpOnly JWT-кука, живёт 12 часов, недоступна из JS в браузере.
- Пароли профилей (для публичного входа на сайт) хранятся как bcrypt-хеши в `data/db.json`.
- `.gitignore` уже настроен так, чтобы `.env` и `data/db.json` не попадали в публичный репозиторий по умолчанию — если будешь пушить в **публичный** GitHub-репозиторий, лучше исключить и `data/db.json`, чтобы не палить контент раньше времени (или сделай репозиторий приватным).

## 4. Бесплатный хостинг (нужен именно бэкенд, не просто статика)

Это уже не просто HTML-файл — здесь работает Node-процесс с собственным диском под `data/db.json`. Статические хостинги (Netlify/Cloudflare Pages из прошлой версии) сюда **не подойдут** — нужен хостинг, который держит процесс живым.

### Render (проще всего, есть бесплатный тир)
1. Залей проект в GitHub-репозиторий (приватный, если не хочешь светить сюжет АРГ раньше времени).
2. render.com → New → Web Service → подключи репозиторий.
3. Build command: `npm install`. Start command: `npm start`.
4. В разделе Environment добавь `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `JWT_SECRET`, `NODE_ENV=production`.
5. **Важно**: на бесплатном тире Render диск эфемерный — при каждом редеплое `data/db.json` сбросится к тому, что лежит в репозитории. Если хочешь, чтобы правки из админки переживали редеплой, добавь Render Disk (Persistent Disk, платная опция) с точкой монтирования в `/opt/render/project/src/data`, либо переходи на Railway/Fly (см. ниже).

### Railway
1. railway.app → New Project → Deploy from GitHub repo.
2. Пропиши те же переменные окружения в Variables.
3. У Railway есть Volumes — подключи volume к папке `data/`, тогда правки из админки будут сохраняться постоянно даже между редеплоями.

### Fly.io
1. `fly launch` в папке проекта (создаст `fly.toml`).
2. `fly volumes create arrs_data --size 1` и примонтируй его на `/app/data` в конфиге.
3. `fly secrets set ADMIN_USERNAME=... ADMIN_PASSWORD=... JWT_SECRET=...`
4. `fly deploy`.

### Свой VPS
Самый надёжный вариант для долгоживущего АРГ: обычный `node server.js` за pm2/systemd + nginx как реверс-прокси с HTTPS (Let's Encrypt). Диск постоянный по умолчанию, ничего докупать не надо.

## 5. Структура проекта

```
server.js                  — точка входа Express
src/db.js                  — файловое JSON-хранилище (data/db.json)
src/auth.js                — админ-логика: пароль только в env, JWT-сессии
src/routes/
  adminAuth.js              — вход/выход/проверка сессии админки
  crudFactory.js             — общий CRUD-роутер (переиспользуется командами/цепочками/страницами/пасхалками)
  adminProfiles.js           — профили (с хешированием пароля)
  adminCommands.js, adminChains.js, adminPages.js, adminEggs.js
  adminSettings.js           — настройки сайта
  publicApi.js                — всё, что видит обычный посетитель (вход, команды, страницы)
public/
  index.html, css/site.css, js/site.js   — публичный терминал-сайт
  page.html                              — шаблон для страниц из цепочек
  admin/                                 — панель администратора (HTML/CSS/JS)
data/db.json                — вся база (кроме пароля админки — тот только в .env)
```

## 6. Дальнейшие идеи для развития (не реализовано, но легко добавить)

- Серверное отслеживание прогресса каждого посетителя по цепочкам (сейчас цепочки проверяются "без памяти" — любой правильный код срабатывает в любой момент).
- Загрузка файлов (портреты/арт) прямо через админку вместо вставки ссылки/base64 вручную.
- Полноценная БД (SQLite/Postgres) вместо JSON-файла, если профилей станет очень много или нужен параллельный доступ с нескольких серверов.
